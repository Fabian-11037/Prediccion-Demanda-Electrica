12. Reproducibilidad y procedencia#

Las fuentes del libro conservan el código y las salidas de cada análisis. El entorno documental se separa del entrenamiento. Las rutas se resuelven a partir de la raíz del repositorio y las fechas se interpretan en America/Bogota.

La sección de inferencia en vivo permite ejecutar los modelos en el navegador, modificar su historia y descargar las trayectorias.

Manifiesto de entradas del análisis#

Las huellas SHA-256 identifican el contenido binario exacto. Se incluyen fuentes numéricas, titulares, archivos externos y el panel consolidado; los resultados de modelos se identifican por separado mediante su registro de artefactos.

def sha256_archivo(path):
    h=hashlib.sha256()
    with path.open('rb') as f:
        for bloque in iter(lambda:f.read(1024*1024),b''):
            h.update(bloque)
    return h.hexdigest()

rutas=set(p for p in (ROOT/'data/raw/numeric').rglob('*') if p.is_file())
rutas.update(p for p in (ROOT/'data/external').rglob('*') if p.is_file())
rutas.update([ROOT/'data/raw/noticias/titulares.parquet',ROOT/'data/processed/panel_horario.parquet',
    ROOT/'data/processed/feature_registry.json',ROOT/'data/processed/diccionario_datos.json'])
manifiesto=pd.DataFrame([{'archivo':p.relative_to(ROOT).as_posix(),'bytes':p.stat().st_size,
    'sha256':sha256_archivo(p)} for p in sorted(rutas)])
manifiesto.to_csv(ROOT/'results/jbook/manifiesto_entradas.csv',index=False)
n_archivos=len(manifiesto); total_gb=float(manifiesto['bytes'].sum()/1e9)

El manifiesto registra 59 archivos y 0.06 GB de entradas. Sus huellas permiten detectar cambios de versión antes de reconstruir el análisis. El diccionario y el registro de disponibilidad complementan la identidad binaria con las definiciones semánticas y temporales.

Ejecución en Windows y Linux#

Crear un entorno con la versión de Python registrada y usar el archivo de dependencias fijadas. Los comandos siguientes se ejecutan desde la raíz; la activación del entorno depende del sistema operativo.

Windows#

python -m venv .bookenv
.bookenv\Scripts\python.exe -m pip install -r requirements-book.lock.txt
.bookenv\Scripts\jupyter-book.exe build book --warningiserror --keep-going
.bookenv\Scripts\python.exe scripts\verificar_jbook.py

Linux#

python3 -m venv .bookenv
.bookenv/bin/python -m pip install -r requirements-book.lock.txt
.bookenv/bin/jupyter-book build book --warningiserror --keep-going
.bookenv/bin/python scripts/verificar_jbook.py

Estos comandos construyen el libro con las salidas conservadas. execute_notebooks: off evita reevaluar las celdas durante esa construcción. Para recalcular los análisis se utiliza python scripts/crear_jbook.py; para reconstruir solo la evaluación, python scripts/reorganizar_capitulo10.py. La recalculación requiere las entradas e instantáneas indicadas en la procedencia; los diagnósticos de redes conservan su entorno separado.

Los análisis documentales se ejecutan por CPU. El entrenamiento de las configuraciones seleccionadas utiliza requirements-entrenamiento.txt y scripts/entrenar_arquitectura.py, con --dispositivo auto, cpu o cuda. La instalación de PyTorch debe ser compatible con el dispositivo y su controlador. El código completo y los comandos por modelo se muestran en el pipeline compartido. La comprobación funcional de las 15 configuraciones se ejecutó en Windows con CPU; Linux y GPU requieren comprobación en sus propios entornos.

Construcción y verificación del libro#

La construcción local utiliza los cuadernos con sus salidas, las fichas de arquitectura y los recursos de book/. La revisión comprueba la estructura de los cuadernos, las interpretaciones junto a las figuras y los enlaces internos del HTML generado. El directorio de salida se especifica con --path-output.

Procedencia de modelos y reconstrucción#

Las cuatro familias de demanda/calendario conservan el commit d1ae9a4e09dd1dead4af1329f16aa3e8d0f2c3d3 y su registro de artefactos; el índice SHA-256 identifica 2.304 archivos. Las arquitecturas ampliadas proceden del commit 66111003f387b8452b1fc690dbc7fc503d5570df y de los paquetes consolidados. El inventario conserva pesos, escaladores, historias, predicciones y métricas por semilla; el control N compartido se cuenta una vez. TFT utiliza el paquete seleccionado por rigor del procedimiento y fidelidad arquitectónica.

El benchmark de referencia integra 75 realizaciones finales de quince procedimientos, con cinco semillas cada uno, y dos referencias deterministas. M4ₙ añade diez realizaciones alineadas con los mismos orígenes. Las métricas se reconstruyen con predicciones conservadas y orígenes alineados. Metadatos de ajuste y validación y cobertura de diagnósticos identifican el alcance de cada análisis. TGForecaster conserva cinco realizaciones por variante.

Para reconstruir la evaluación integrada se ejecuta python scripts/reorganizar_capitulo10.py; después, jupyter-book build book --warningiserror --keep-going y python scripts/verificar_jbook.py. El generador completo scripts/crear_jbook.py integra la misma ampliación al finalizar. Los datos de predicción y las entradas documentales deben conservar su inventario de procedencia. La reproducción del análisis documental usa CPU; la inferencia y el entrenamiento requieren PyTorch compatible con CPU, CUDA o ROCm según el procedimiento y dispositivo. La reconstrucción del libro no inicia entrenamiento.

Reconstrucción y revisión de consistencia#

La narrativa de resultados se genera mediante scripts/narrativa_resultados.py a partir del benchmark, contrastes, MCS, selección y diagnósticos conservados. Las celdas Markdown identifican su función mediante metadatos; las cifras y conclusiones se actualizan durante la reconstrucción.

La revisión vigente y el resumen con huellas de procedencia documentan el inventario y las fuentes utilizadas.

Reproducción de la evaluación y sus diagnósticos#

Las fuentes de book/ incluyen los cuadernos con sus salidas, las fichas de arquitectura, los esquemas y los archivos descargables. jupyter-book build book --warningiserror --keep-going construye el HTML desde esas fuentes, con la ejecución de cuadernos desactivada.

Los CSV y NPZ de results/evaluacion_e2/ y results/diagnosticos_ampliados/ contienen las pérdidas, contrastes, curvas y mediciones utilizadas en las figuras. La reconstrucción de la presentación utiliza estos archivos y las predicciones conservadas:

python scripts/reorganizar_capitulo10.py
jupyter-book build book --warningiserror --keep-going
python scripts/verificar_jbook.py

scripts/actualizar_diagnosticos_jbook.py actualiza las figuras a partir de las mismas mediciones. scripts/reconstruir_evaluacion.py vuelve a ejecutar el código analítico del cuaderno integrado con las entradas verificadas por SHA-256. Ninguno de estos procedimientos reajusta modelos.

La repetición de inferencia requiere, además, los checkpoints, escaladores y vectores E5 identificados en fuentes_diagnosticos.json. Su ubicación se configura mediante DEMANDA_ARTEFACTOS, apuntando al directorio que contiene consolidado/indice_modelos.json y fuentes/. Estos archivos binarios no son necesarios para construir el libro ni reconstruir las gráficas desde las mediciones. Las nuevas mediciones utilizan el entorno requirements-inferencia.lock.txt y los comandos siguientes:

python scripts/diagnosticos_ampliados.py --fase inferir --workers 4
python scripts/diagnosticos_ampliados.py --fase latencia

reproduccion_semillas.csv documenta la correspondencia con las predicciones conservadas; entorno.json identifica las condiciones de la medición de latencia.

N-BEATS y TimesNet: entradas y reproducción#

Las claves nuevo_nbeats__N y nuevo_timesnet__N identifican cinco realizaciones de cada red. Configuraciones, escaladores, historias y predicciones canónicas se conservan en results/evaluacion_e2/entradas/adicionales/. TimesNet utiliza yhat_lote1_kwh de la reevaluación por origen; N-BEATS conserva sus predicciones originales. Las etiquetas provienen del panel congelado en doble precisión.

La selección y la parada interna mantienen sus registros de desarrollo. Para TimesNet, la prueba y las perturbaciones reciben un único origen en cada llamada. Los pesos se verifican mediante el inventario SHA-256 de diez checkpoints; la procedencia de la integración y el protocolo de diagnósticos acompañan los resultados.

integrar_top10.py normaliza las entradas y mantiene la copia de procedencia. estadistica_e2.py calcula las familias completas de contrastes sobre las predicciones guardadas. reorganizar_capitulo10.py reconstruye la evaluación y las fichas de ambas arquitecturas; la aplicación estática utiliza los mismos resultados mediante su exportador.

python scripts/estadistica_e2.py
python scripts/reorganizar_capitulo10.py
python dashboard/scripts/export_data.py
jupyter-book build book --warningiserror --keep-going
python scripts/verificar_jbook.py

Estos pasos leen los resultados disponibles. Los pipelines de ajuste e inferencia se documentan en las fichas de arquitectura y permanecen separados de la construcción del libro.

Reproducción de M4ₙ#

scripts/integrar_m4_resultados.py reconstruye las métricas, tablas y figuras de M4ₙ desde las predicciones e historiales de diez semillas conservadas en results/m4_cierre_gpu_20261123/reducido_B/. La escala semanal y los comparadores proceden del benchmark; TimesNet se verifica con sus cinco predicciones de lote uno. Los bloques analíticos se muestran completos en la sección de resultados.

Ejecutar python scripts/integrar_m4_resultados.py desde la raíz regenera únicamente la documentación y los resúmenes derivados. El manifiesto registra las huellas de los archivos utilizados. No se importan módulos de redes ni se cargan pesos; los contrastes se leen de los resultados guardados y conservan sus ajustes por multiplicidad.

Evaluación complementaria e inferencia portable#

Los archivos de results/cierre_e3_sin_entrenar_20261124/ conservan las pérdidas diarias, las 102 comparaciones complementarias, el MCS y los diagnósticos del núcleo. La calibración común vigente utiliza results/incertidumbre_comun_20261125/; la tabla de coste utiliza results/tabla_maestra_20261125/. scripts/integrar_cierre_e3.py reconstruye tablas y figuras desde estos resultados; los módulos de medición y exportación se muestran completos en la evaluación.

El paquete CPU contiene los tres expertos, M1 y la memoria en cinco módulos ONNX, escaladores, contrato de entradas preparadas, ejemplos y manifiesto. Se verificó en un entorno Windows nuevo con Python 3.13, NumPy y ONNX Runtime. Los datos propios deben respetar la alineación temporal y las transformaciones del contrato. El contenedor Linux queda preparado mediante Dockerfile y su ejecución requiere verificación en esa plataforma.

Después de extraer el paquete, su comprobación se ejecuta con:

python -m pip install -r requirements.txt
python ejecutar.py --verificar

Correspondencia métrica de la exportación#

El panel prefijado de verificación contiene cuatro fechas históricas y 96 intervalos, con la semilla 101. El MASE nativo es 0,42716155 y el exportado 0,42716146; la diferencia es -9.36e-08. La comparación se limita al panel de verificación y no sustituye el benchmark de 1.461 días y diez realizaciones. Resultados por fecha.

"""Contrasta el MASE de la exportación en cuatro días fijados en el round-trip."""
from pathlib import Path
import json,sys,importlib.util
ROOT=Path(__file__).resolve().parents[1]
sys.path.append(str(ROOT/'.bookenv/Lib/site-packages'))
import numpy as np
import pandas as pd
OUT=ROOT/'results/auditoria_e3_final_20261124';OUT.mkdir(exist_ok=True)
PACKAGE=ROOT/'results/cierre_e3_sin_entrenar_20261124/paquete_m4_cpu'
Q=215617.90361589016

def main():
 spec=importlib.util.spec_from_file_location('m4_onnx_auditado',PACKAGE/'ejecutar.py');runner=importlib.util.module_from_spec(spec);spec.loader.exec_module(runner)
 protocol=json.loads((PACKAGE/'exportacion.json').read_text(encoding='utf-8'))
 panel=pd.read_parquet(ROOT/'data/processed/panel_horario.parquet',columns=['y_demanda_real_kwh'])
 rows=[];native=[];onnx=[];labels=[]
 for i,record in enumerate(protocol['resultados']):
  date=record['origen']
  if date>='2026-01-01':continue
  pred=np.asarray(runner.run(PACKAGE,PACKAGE/f'ejemplo_{i}.npz')['prediccion_kwh'])
  original=np.load(PACKAGE/f'esperado_{i}.npy',allow_pickle=False)
  index=pd.date_range(date,periods=24,freq='h',tz='America/Bogota');y=panel.loc[index,'y_demanda_real_kwh'].to_numpy()
  native.append(original);onnx.append(pred);labels.append(y)
  rows.append(dict(origen=date,MASE_nativo=float(np.abs(original-y).mean()/Q),MASE_ONNX=float(np.abs(pred-y).mean()/Q),max_diferencia_kwh=float(np.abs(pred-original).max())))
 n=np.stack(native);o=np.stack(onnx);y=np.stack(labels)
 summary=dict(semilla=101,n_dias=len(rows),n_intervalos=int(y.size),fechas=[r['origen'] for r in rows],
  MASE_nativo=float(np.abs(n-y).mean()/Q),MASE_ONNX=float(np.abs(o-y).mean()/Q),
  diferencia_MASE=float((np.abs(o-y).mean()-np.abs(n-y).mean())/Q),
  max_diferencia_kwh=float(np.abs(o-n).max()),entrenamiento=False,
  alcance='Panel de verificación de cuatro fechas prefijadas; no es el benchmark completo de1461días ni promedio de diez semillas')
 pd.DataFrame(rows).to_csv(OUT/'roundtrip_metricas.csv',index=False)
 (OUT/'roundtrip_metricas.json').write_text(json.dumps(summary,ensure_ascii=False,indent=2),encoding='utf-8')
 print(json.dumps(summary,ensure_ascii=False))

if __name__=='__main__':main()
